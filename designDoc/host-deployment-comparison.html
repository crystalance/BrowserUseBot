24/7 Host Deployment — Cloud Comparison & Recommendation

Browser-Agent Platform · v0.1 · 2026-06-29 · China-origin operator, dual China + global cloud, persistent-now / lightweight-later

1. What the host must actually do

The agent is a long-lived process running a headful Chrome (browser-use over CDP) with a persistent profile, a Telegram gateway, a scheduler, and a short-lived CDP-screencast remote view. Selecting a host is about matching that workload, not raw price.

RequirementWhy it matters
Always-on, statefulPersistent Chrome profile + workspace must survive restarts → needs a persistent disk, not ephemeral functions.
Headful browser-capable~1.5–2 GB RAM minimum; CPU spikes during page render. Rules out micro/serverless tiers.
Reliable outbound to LLM + TelegramCritical in China: Anthropic/OpenAI/Telegram are largely blocked/throttled → biggest decision driver.
Inbound for remote-view linkSolved by Cloudflare Tunnel (egress only) → no public IP / ICP filing needed.
Cheap, single small nodeOne user, one agent. A 2 vCPU / 2–4 GB VPS is plenty. Occam's razor.

5. Persistent now, lightweight later

Phase 1 — now

Persistent server

One always-on VPS. Headful Chrome + persistent profile stays warm → instant tasks, sessions survive, simplest to reason about. Cost ~$6–15/mo. Right for M1–M5.

Phase 2 — later

Lightweight on-demand

Spin a sandbox (Fly Machine / E2B) per task, restore profile from object storage, tear down. Pay only when working. Cost approaches $0 idle, but cold-start + state restore add latency. Worth it only if the box is mostly idle.

Verdict: persistent first — a single user's bot is idle most of the day but cheap enough that on-demand complexity isn't justified yet. Keep the door open via the abstraction below.

6. The host abstraction (implement both)

class HostProvider(Protocol):
    async def ensure_running(self) -> None: ...      # boot/keep node alive
    async def profile_dir(self) -> str: ...          # persistent Chrome profile path
    async def restore_state(self) -> None: ...       # pull profile/workspace
    async def persist_state(self) -> None: ...       # push profile/workspace
    async def expose(self, port:int) -> str: ...     # tunnel → short-lived URL
    async def teardown(self) -> None: ...            # noop (persistent) / kill (light)

PersistentVpsHost   # DO/AWS/Aliyun HK: local disk, no teardown, tunnel
OnDemandSandboxHost # Fly/E2B: object-store profile, expose, teardown

The runner depends only on HostProvider; persistent vs lightweight and CN vs global become config, not code.

7. China-specific cautions

  • Mainland ECS cannot reach Anthropic/OpenAI/Telegram → use HK/SG region.
  • No ICP filing needed: remote view goes over Cloudflare Tunnel (egress only).
  • Cross-border payments: Alibaba/Tencent accept CN cards; global providers need an international card.
  • Keep targets ToS-clean; no evasion (matches platform non-goals).
